## Artifact and naming conventions

| Path | Purpose |
|---|---|
| `training/scripts/` | Download, training, evaluation, comparison and export scripts. |
| `training/configs/` | Class taxonomy and dataset-source manifests. |
| `training/runs/<run_id>/` | Ultralytics outputs and checkpoints. |
| `models/GRU/<arch>/runs/<run>/` | GRU checkpoints, configs, per-run reports. |
| `evaluation/benchmarks/<benchmark_id>/` | Compact CSV / JSON / Markdown results worth keeping. |
| `evaluation/benchmarks/figures/` | Generated by `evaluation/generate_report_figures.py`; safe to delete and regenerate. |
| `models/yolo/<model_id>/README.md` | Model registry entry. |
| `simulation/datasets/sanpo/valid_streams.json` | The 462 curated SANPO-Real sessions. |
| `simulation/datasets/sanpo/session_audit.json`, `official_split.json` | Per-session fps / intrinsics / masks, and SANPO's official train/test split (`tools/audit_sanpo_sessions.py`). |
| `evaluation/benchmarks/heldout_official_split/`, `threat_engine_replay/` | Final arrival-ranking and system-replay results on the official test split. |
| `data/` | Local raw and processed data; never committed. |
| `.env` | Local secrets such as `ROBOFLOW_API_KEY`; never committed. |

Use names that identify model, task and version (e.g. `cpe_yolo26n_hazards_v3_from_base`), never
`test`, `new`, `final` or `latest`.

## Maintenance rules

- Keep this index pointed only at files that exist.
- Design changes go in `architecture.md`; status in `progress.md`; backlog in `pending_work.md`.
  When a pending item is finished, move it to `progress.md`.
- Benchmark data goes in `evaluation/benchmarks/`; docs summarise only the durable conclusion.
- Label every latency number as measured (and on which device) or simulated.
- When a benchmark changes, re-run `evaluation/generate_report_figures.py`.
- Update the main `README.md` project tree whenever files, folders, models or benchmarks are
  added or moved.
- Prefer adding a section to an existing doc over creating a new file.
